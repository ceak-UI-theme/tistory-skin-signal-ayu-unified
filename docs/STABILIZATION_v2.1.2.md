# v2.1.2 안정화 후보 검증

검토일: 2026-10-31 (Asia/Seoul). 시작 기준: `a50e791befdc2b1201099235dc1334e54599d270`.
작업 시작 시 원격 main과 HEAD가 기준 커밋으로 일치했고 작업트리는 깨끗했다.
Issue #2의 최신 댓글(6542398564)을 다시 확인하고 기존 v2.1.1 병합 및 수정 사항을 보존했다.

## 수정 범위와 결정

### P1-1: 표

기존 Ayu 규칙이 모든 본문 셀의 배경·글자·테두리 색을 `!important`로 덮어써
에디터의 style1~16과 명시적 셀 스타일을 무효화했다. 해당 강제 규칙을 제거했다.
새 스타일은 JS가 식별한 `.ayu-content-table`에 한정한다. `.another_category`, `.tt-calendar`,
`[data-signal-system-table]` 내부 표에는 클래스·스크롤 래퍼를 추가하지 않는다.

- 라이트는 에디터 스타일을 유지하되 일부 헤더의 텍스트 대비를 보정한다.
- 다크는 배경을 테마 토큰으로 매핑하며 줄무늬/헤더의 시각적 구분을 유지한다.
- 가로선 전용(style8~11), 투명 테두리(style16), 헤더 강조선(style1~3/9~11)을 보존한다.
- 인라인 지정 색·크기는 작성자 의도를 우선한다. 따라서 모든 작성자 지정 색 조합의 대비를 강제로 보장하지 않는다.
- 표를 의미 있는 table 구조로 유지하며 colspan/rowspan을 변경하지 않는다.
- 래퍼는 이름이 있는 키보드 접근 가능한 region이고 가로 스크롤을 제공한다.
- 긴 단어는 줄바꿈하고, 고정 너비/코드/다중 열이 필요한 경우 래퍼 안에서 스크롤한다.

### P1-2: 최근 공지

[티스토리 공식 최근 공지 문서](https://tistory.github.io/document-tistory-skin/sidebar/recent_notice.html)는
`s_rct_notice_rep`에서 링크·제목을 명시한다.
[일반 공지 문서](https://tistory.github.io/document-tistory-skin/contents/notice.html)의 상세/인덱스 치환 범위와 구분했다.
상단 최근 공지에서는 요약·날짜와 해당 빈 DOM을 제거하고 `공지` 라벨과 제목 링크만 표시한다.
일반 공지 템플릿의 요약·날짜는 해당 블록에 남겼다. 외부 페이지 요청으로 요약을 보충하지 않는다.
공지 없는 페이지의 일반 글 메타는 공지 전용 선택자에 영향받지 않는다.

### P1-3: 접근성

메뉴·프로필·카테고리·검색의 컨트롤을 jQuery 의존과 분리하고 기존 Area의 중복 핸들러를 제거했다.
초기화는 중복 실행해도 이벤트를 재등록하지 않는다.

- 연결된 ID/aria-controls/aria-expanded, 메뉴·목차 대화상자의 이름/aria-modal 반영.
- 모바일 메뉴·목차에서 배경 inert 및 Tab/Shift+Tab 순환, Escape/닫기로 포커스 복귀.
- 모바일 검색창 Escape는 숨겨진 검색 버튼 대신 메뉴를 닫고 메뉴 버튼으로 복귀.
- 메뉴 820px→데스크톱, 목차 1279px→1280px 전환 시 상태·배경 inert·포커스 복원.
- 일반 버튼의 Enter/Space, 프로필/카테고리 Escape, 검색 열기·포커스 및 blur 처리.
- focus-visible 색을 링크 토큰으로 변경하고 라이트 링크/보조 글자색 대비 개선.

### P1-4: 목차

본문 템플릿에 post/notice/page/protected 종류를 표시한다. 공지·정적 페이지는 전역 entryInfo나
카테고리 링크의 우연한 존재에 의존하지 않는다. 목록 및 본문 없는 잠긴 보호글에는 표시하지 않는다.
현재 본문 구조에서 가장 높은 헤딩 레벨과 그 다음 레벨의 두 단계 목차를 유지한다.

한글/중복 ID/외부 ID/기존 앵커/특수문자와 재초기화를 처리하며,
클릭 시 인코딩한 해시를 기록하고 초기 한글 해시를 고정 헤더 아래로 정렬한다.
모바일 목차가 열린 채 1280px 이상으로 전환돼도 숨겨진 패널에 포커스를 남기지 않는다.

### 광고·읽기 기능

목록 상·하단 광고 치환자는 각각 한 번씩 보존하고 바깥 컨테이너의 너비·넘침을 제한했다.
테스트는 970px iframe/div 자리표시자로 레이아웃만 확인한다.
AdSense 요청·수익·노출 성공을 테스트하거나 주장하지 않는다.
코드 복사, 테마 토글 및 aria-pressed, 읽기 시간·읽기 진행률 기능을 유지했다.

## 자동 검증

- `npm run check`: parse5 HTML 구문, Tistory 블록 중첩/필수 치환자, JS 및 인라인 스크립트 문법,
  PostCSS 구문, 인코딩, HTML 사본 동기화 및 HTML/CSS/CHANGELOG/XML 버전 정합성.
- `npm test`: 기존 테스트 6개 유지 및 템플릿 기반 통합 회귀 테스트 추가.
  외부 네트워크를 차단한 fixture를 사용하고 브라우저 pageerror가 없음을 확인한다.
- 뷰포트: 320, 375, 390, 820, 1280, 1440px × Light/Dark.
  모든 조합에서 표·공지/광고 레이아웃·테마 토큰을 확인한다.
  메뉴·목차의 키보드/전환은 해당 UI가 실제 노출되는 뷰포트에서 별도로 확인한다.
- 표: style1~16, 일반 고정폭 표, 긴 문자열·코드, colspan/rowspan, 명시적 셀 색,
  에디터 테두리 변형과 시스템 표 제외, 재초기화 시 중복 래퍼 없음.
- 공지 유무·일반 글·공지·보호글·정적 페이지·목록, 목차 클릭/스크롤 활성·오프셋·초기 해시,
  기존 앵커, H1/H2 및 H3/H4 구조, 모바일 포커스 순환/반응형 전환.
- v2.1.1 코드 복사 성공·실패 및 기존 DOM/이벤트 보존 검사 유지.
- 테마별 본문/보조/링크 토큰과 기본 배경 대비를 수치 검사(4.5:1 이상).
- `python3 scripts/verify_zip.py`: XML 파싱, ZIP CRC, 중복/필수/제외 파일, 모든 배포 파일의
  현재 소스와 바이트 일치, 캐시 버전. 패키지 전체를 허용 목록과 대조한다.
- GitHub Actions는 push/PR에서 npm ci → 정적 검사 → Chromium 브라우저 검사 → 커밋 ZIP 검사
  → 새 ZIP 빌드·검사를 실행한다. lockfile을 포함해 의존성을 고정한다.

## 운영에서 별도로 확인할 항목과 수행 방법

아래 항목은 로컬 fixture 통과로 완료 처리하지 않는다. 실제 티스토리 적용은 수행하지 않았다.

1. 스킨 편집기 원본과 자산을 백업한 뒤 별도 승인된 미리보기/테스트 블로그에서 후보를 적용한다.
2. 홈(공지 있음/없음), 카테고리, 검색, 태그, 방명록, 일반 글, 공지, About/Privacy/Contact,
   보호글 잠김/해제 상태를 로그인·로그아웃 각각 확인한다.
3. 공지 제목·링크가 실제 치환되고 요약/날짜 빈 요소가 사라졌는지 응답 HTML과 화면에서 확인한다.
4. 실제 에디터로 저장한 표 16종·병합 셀·HTML 표를 열어 computed style, 가로 스크롤,
   시스템 관련글 표와 본문 폭을 대표 뷰포트·두 테마에서 확인한다.
5. 검색을 Enter로 제출해 실제 검색 결과를 확인한다. 잠금 해제·댓글·메뉴·스크린리더 이름과
   포커스 복귀·페이지 탐색을 실플랫폼에서 확인한다.
6. 개발자 도구에서 JS 캐시 쿼리 2.1.2와 실제 응답을 확인하고 새로고침·저장 테마·초기 해시를 점검한다.
7. 실제 광고 요청/슬롯 채움/동의·로그인 조건은 운영자가 광고 콘솔과 네트워크로 확인한다.
   슬롯이 비어 있거나 차단된 상태도 레이아웃이 유지되는지 확인한다.

운영 적용, GitHub Release 발행, PR 자동 병합, Issue #2 종료는 이 작업의 산출물에 포함하지 않는다.
Issue #2는 OPEN으로 유지한다.
